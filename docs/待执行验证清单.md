## V2. 零基建默认路径冒烟（不启 Docker）

**目的**：验证"clone → 配 key → 启动 → 第一个查询"默认路径真实可跑。

```powershell
cd rag-kb
mvn spring-boot:run          # 默认内存模式，不依赖任何容器
```

| 步骤 | 命令 | 判定标准 |
|---|---|---|
| 启动 | 看日志 | `Tomcat started on port 8000`；**无** DataSource/Milvus/rerank 连接报错 |
| 入库 | `curl.exe -X POST localhost:8000/api/ingest -H "Content-Type: application/json" -d '{\"path\":\"data/docs\"}'`（chcp 65001 后执行） | 返回含 `chunks`、`filesOk`、`filesFailed` 字段（新契约）；`filesFailed: 0` |
| 问答 | `curl.exe -X POST localhost:8000/api/query -H "Content-Type: application/json" -d '{\"question\":\"入职满3年的员工有几天年假？\"}'` | `refused: false` 且 answer 带 `[1]` 引用；若 401/invalid api key → 回 V0 设 key |
| MCP | `curl.exe -N localhost:8000/sse` | SSE 连接能建立（收到 `event:` 行即可 Ctrl+C） |

## V3. 持久化模式（Postgres + warmup，DAT-01 复验）

```powershell
docker compose up -d postgres
mvn spring-boot:run "-Dspring-boot.run.profiles=persistent"
```

- 启动日志出现 warmup 且 `chunks > 0`（先 ingest 一次再重启验证）
- **重启不丢验证**：ingest → 停应用 → 再启 → 直接 `/api/query` 能答，**无需重灌**
- `curl.exe localhost:8000/api/eval/runs` 返回 `[]` 或历史 run 列表（服务可用即算过）

## V4. GPU Rerank（台式机专属，行动项 G1）

```powershell
docker compose -f docker-compose.yml -f docker-compose.gpu.yml --profile rerank up -d
docker ps --filter name=rag-kb-rerank          # STATUS 需为 healthy（首拉模型约 2GB，宽限 120s）
curl.exe -X POST localhost:8087/rerank -H "Content-Type: application/json" -d '{\"query\":\"test\",\"texts\":[\"a\",\"b\"]}'   # 期望返回 scores 数组
```

persistent profile 下 `rerank.enabled=true` 已生效，然后：

| 场景 | 操作 | 判定标准 |
|---|---|---|
| 正常精排 | `POST /api/query` | 响应正常、日志**无** rerank 降级 WARN |
| 真降级（关键） | `docker stop rag-kb-rerank` 后再 `/api/query` | **仍返回 200**（融合名次截断）+ 日志 WARN 留痕——这是 🚨2 修复的现场证据 |
| 乱序响应 | 可跳过（单测已覆盖 index 边界校验） | — |
