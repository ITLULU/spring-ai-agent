# Agent 学习 12 周执行计划

> 配套文档：《学习路径评审与调整建议.md》｜ 项目脚手架：`rag-kb/`
> 节奏：每周投入约 20-25h（工作日 3-4h/天 + 周末集中）。每阶段末尾留 3 天缓冲。
> 贯穿动作：每周 2h 原理学习（与当周实践挂钩）+ 1 篇 200 字精读笔记（问题/方案/可借鉴点）。

## 关键决策（已定死，见评审文档第四节）
- 框架：**Spring AI**（LangChain4j 仅作面试口头对比）
- 阶段2项目：**工单智能处理 Agent**（复用阶段1的 RAG 作为检索工具）
- 向量库：**先内存(SimpleVectorStore)跑通评测闭环 → 第3周切 Milvus**

## 阶段 1：生产级 RAG（第 1-4 周）

### 第 1 周 — 跑通最小闭环 + 文档解析
- **实践**：`rag-kb` 脚手架起服务；接一个 OpenAI 兼容 Embedding + Chat；实现 TXT/Markdown/PDF 解析（PDFBox）；固定长度切块入库；单轮问答能返回带来源的答案。
- **原理线**：Embedding 原理（向量空间、余弦相似度、为什么语义相近向量距离近）。
- **验收**：`mvn test` 绿；本地上传 1 篇文档 → 提问 → 返回答案 + `[source]` 引用。
- **精读**：Spring AI 官方 RAG / Documents 章节。

### 第 2 周 — 切块策略对比 + 混合检索
- **实践**：实现 3 种切块（固定长度 / 递归字符 / parent-child），跑同一评测集对比；实现 BM25 关键词检索；向量+BM25 用 RRF 融合成混合检索。
- **原理线**：bi-encoder（检索）vs cross-encoder（精排）差异；词法检索 vs 语义检索的召回偏差。
- **验收**：评测集 ≥ 50 条；能报出"固定切块 vs parent-child vs +混合检索"三组对比的召回率数字（哪怕是初步的）。
- **精读**：RAGAS 指标定义文档 / 一篇混合检索落地博客。

### 第 3 周 — Rerank + 切 Milvus + 幻觉治理
- **实践**：接入 Rerank（托管 API 或本地 bge-reranker），对比 Rerank 前后 Top-K 命中；切向量库到 Milvus（装 Docker 或用远程 Milvus 实例）；实现引用溯源强化 + 低置信度拒答机制。
- **原理线**：cross-encoder 精排为什么贵但准；拒答阈值如何权衡"漏答 vs 幻觉"。
- **验收**：Milvus 后端跑通全链路；Rerank 带来的准确率提升有数字；拒答机制对"答案不在库中"的题能正确拒答。
- **精读**：Milvus 官方 hybrid search 文档 / 一篇幻觉治理分享。

### 第 4 周 — 评测体系定型 + 缓冲/README（含 3 天缓冲）
- **实践**：把评测脚本固化成可复跑命令（LLM-as-Judge 打忠实度/相关性/召回命中率）；构造 80-100 条测试集（含 20% 拒答题，反向出题法见评审）；写 GitHub README（技术决策 + 优化前后数字）；整理"效果-成本"记录表。
- **原理线**：RAG 评测指标体系（faithfulness / answer relevancy / context precision & recall）。
- **里程碑 M1**：`rag-kb` 挂 GitHub，README 有"优化前 X% → 优化后 Y%"、架构图、技术选型理由。**阶段1完成标志。**

## 阶段 2：工单智能处理 Agent（第 5-8 周）

### 第 5 周 — 工单领域建模 + Function Calling 基础
- **实践**：定义工单数据模型 + 状态机（`NEW / AUTO_RESOLVED / PENDING_HUMAN / FAILED / RETRYING`）；用 H2/MySQL 持久化；接入 Function Calling，实现 2-3 个工具（查工单、查知识库、写处理记录）。
- **原理线**：Function Calling 协议（schema 定义、模型如何决策调用、结果如何回填）。
- **验收**：给定一句用户诉求，Agent 能正确选择并调用工具，参数解析正确。

### 第 6 周 — 多工具编排 + 会话状态管理
- **实践**：把阶段1的 RAG 封装成 Agent 的一个检索工具（串联！）；实现可控工作流（代码节点式编排，非裸调模型）；会话上下文状态管理（多轮、槽位填充、超时）。
- **原理线**：Agent 规划范式（ReAct、Plan-and-Execute 对比）。
- **验收**：一条工单从"受理→检索知识→生成处理建议→状态流转"全自动跑通，多轮会话可追溯。

### 第 7 周 — MCP 协议 + 失败重试/人工兜底
- **实践**：把"工单查询"能力实现为一个 **MCP Server**（对比 Function Calling 讲清差异）；实现失败重试（退避）+ human-in-the-loop 审核兜底（低置信/高风险转人工，带审核接口）。
- **原理线**：MCP 三类原语（tools/resources/prompts）、stdio vs streamable HTTP。
- **缓冲**：本周末 3 天缓冲，补前两阶段欠账。
- **验收**：MCP 工具可被调用；高风险工单正确进入 `PENDING_HUMAN`；状态转移图能画出来。

### 第 8 周 — Agent 收尾 + （穿插）LoRA 微调 Demo + README
- **实践**：Agent 整体串联 + demo 脚本；README + 架构图；**用租用的云 GPU 跑通一个 LLaMA-Factory LoRA 微调 Demo（只承诺跑通流程 + 看懂 loss 曲线，2-3 天封顶）**。
- **里程碑 M2**：工单 Agent 挂 GitHub，README 讲清"可控工作流 + MCP + human-in-the-loop"三大面试点。LoRA Demo 有截图与 loss 曲线。**阶段2完成标志。**

## 阶段 3：补短板 + 面试包装（第 9-12 周）

### 第 9 周 — Python 速通 + 原理补课(上)
- **实践**：能读懂 LangChain/LlamaIndex 的 RAG 与评测脚本；把阶段1某个能力用 Python 走一遍对照。
- **原理**：Transformer/Attention——白板画 Q/K/V 流程，讲清 KV Cache、上下文窗口成本（验收锚点见评审第9条）。
- **验收**：白板上讲清 Attention 计算 + 能改一个 Python 评测脚本的阈值参数。

### 第 10 周 — 原理补课(下) + 选型逻辑
- **原理**：Temperature/Top-p 采样、蒸馏 vs 微调 vs RAG 选型逻辑、上下文窗口与成本。每条准备"什么场景选什么、为什么不选另一条"的话术。
- **精读**：2 个大厂 AI 落地分享（蚂蚁/字节）。

### 第 11 周 — 简历改写 + 系统设计题(上)
- **实践**：按"业务问题 → 技术方案 → 量化结果"重写 RAG/Agent 两段项目经历。
- **系统设计**：精备 2 题——"设计企业知识库系统"、"设计客服机器人如何控制幻觉与成本"。每题画图 + 讲 tradeoff。

### 第 12 周 — 系统设计题(下) + 模拟面试 + 缓冲
- **系统设计**：再备 2 题——"RAG 系统的评测与迭代闭环"、"Agent 工作流的可靠性设计"（你两个项目的自然延伸，性价比最高）。
- **模拟**：3-5 套模拟面试（自我介绍 + 项目深挖 + 系统设计），录音复盘；整理高频追问的"每一行能解释"清单。
- **里程碑 M3**：简历定稿 + 4 道系统设计话术 + 项目答辩可脱稿。**求职就绪。**
