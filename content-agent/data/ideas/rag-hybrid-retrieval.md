# 我用 Spring AI 手搓了一套生产级 RAG，没用 LangChain

## 背景

最近在做企业知识库方向的学习项目，目标是把 RAG 全链路自己实现一遍，而不是调现成框架。
原因很简单：调 API 三行代码谁都会，但真正上线时暴露的问题（召回质量、幻觉、评测）都在框架抽象之下，看不见也调不动。

## 我做了什么

整条链路自己实现：

- 文档切片：实现了 fixed / recursive / parent-child 三种分块策略，做成单变量开关方便对比
- 关键词检索：手写了 BM25 倒排索引 + 中文分词
- 向量检索：本地用 Docker 跑 Milvus（没有 GPU，全部 CPU 环境）
- 混合召回：BM25 + 向量两路结果用 RRF（Reciprocal Rank Fusion）融合
- 重排：接了 rerank，用开关控制启用与否做 A/B
- 评测：自己建了一份 QA 评测集，用 Recall@K 量化检索质量

## 踩到的坑

1. 中文分词直接影响 BM25 效果，切词粒度要配合分块策略一起调，不能孤立优化。
2. 拒答阈值是个权衡点：相似度阈值设高了漏答，设低了容易幻觉，必须靠评测集来定，拍脑袋不行。
3. 没有评测集的 RAG 优化基本等于玄学——加任何一环前，先能量化它带来的变化，否则无法判断是否值得。

## 为什么值得写

大部分中文 RAG 教程停留在「跑通 demo」，很少有人讲「无 GPU、CPU 环境、全链路可评测」这种贴近中小企业真实预算的落地方案。这块是有信息差的。
