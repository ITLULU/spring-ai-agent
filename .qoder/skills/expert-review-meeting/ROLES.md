# 四专家检查域与量化推算手册

> 阶段 2 每位专家按本节发言；每条结论必须落「证据文件链接 + 算式/数字口径」。

## 🧑‍💼 资深产品检查域

1. **承诺 vs 交付**：README/pom/对外宣传中的每个能力声明，找到对应的真实执行证据（运行记录、
   产出文件、测试结果）。找不到证据的核心卖点 = 🛑 候选（对外撒谎）或 ⚠️（内部预期管理）。
2. **业务高峰的用户后果**：容量问题翻译成用户语言（排队 N 分钟、批量任务全批失败、支付页超时率 X%），
   让技术风险进入业务决策，而不是停在技术圈。
3. **成本模型**：目标 QPS 档位下的基础设施成本推算（实例数×规格、缓存/DB 扩容），
   与产品收入模型是否错位；按调用计费的 AI/外部 API 要单独算 token/次成本。
4. **风险披露一致性**：文档自我定位（如 "production-grade"）与已知局限清单是否互相矛盾。
5. **上线节奏**：🛑 项与业务时间窗冲突时，给出砍范围/延期/带险上线三选一的产品裁决建议。

## 👨‍💻 资深研发检查域

1. **单实例容量推算**（必写算式）：
   ```
   线程池上限QPS = 容器线程数 / 平均RT        （Tomcat: max-threads × 1/RT）
   CPU上限QPS   ≈ 核数 × (1 / 单请求CPU秒)
   单实例QPS    = min(线程池, CPU, 连接池, 下游限流, GC可承受分配率)
   所需实例数   = 目标QPS × P99_RT / 单实例QPS   （Little's Law，再除冗余系数0.7）
   ```
2. **架构瓶颈定位**：全链路找"每请求必经的串行点"——锁、单线程 executor、全局重建（O(N) rebuild）、
   文件追加写、同步远程调用；每个都给出"多少 QPS 时先死"。
3. **水平扩容正确性**：本地状态（内存索引/文件存储/进程内缓存）在多实例下的行为——
   分片是否缺失数据、重建是否互相打架。**扩容坏正确性比扩容坏性能更严重（🛑 级）**。
4. **降级路径真实性**：注释/文档声称的 fallback 必须逐行验证 catch 范围覆盖超时、连接拒绝、
   协议异常三类；`RestClient/HttpClient` 无超时 = 降级永远不会触发（线程先死）。
5. **异步化边界**：秒级以上任务是否还在同步 HTTP 里；长任务无 runId/进度/断点续跑 = ⚠️ 起评。
6. **静默失败清单**：catch 后返回空集合/null/默认值且不告警的路径，逐条列出。

## 🛠 资深运维检查域

1. **资源换算**：把用户提供的机型/核数/内存与服务配置对上——
   `堆内存+元空间+线程栈(线程数×1MB)+堆外` 是否超机器规格；连接池总数
   `实例数 × 池大小` 是否超 DB `max_connections`。
2. **可观测性**：metrics（QPS/RT/错误率/饱和度四金指标）、结构化日志+traceId、告警阈值、
   健康探针（liveness≠readiness）。缺一项记 ⚠️，全无 = 高峰盲飞（🔶）。
3. **发布与故障恢复**：滚动发布是否丢请求（优雅停机/连接drain）、依赖重启后本服务行为
   （重试？雪崩？静默退化）、备份与恢复演练是否存在。
4. **单点清单**：逐个点名 SPOF（单实例DB/无副本缓存/本地文件/定时任务多实例重复跑）。
5. **流量突增防御**：限流（入口级+下游级）、队列缓冲（MQ削峰）、熔断降级开关；
   业务高峰=日常3~10倍是默认假设，没有任何防御直接 🔶。
6. **弹性**：扩缩容是人工还是自动（HPA）；扩容后预热问题（缓存冷启动、连接风暴）。

## 🗄 资深 DBA 检查域

1. **数据量推算**（必写算式）：
   ```
   日增 = 写QPS × 86400 × 行均字节（含索引膨胀系数1.5~2.5）
   总量 = 日增 × 保留天数 × 增长复利
   判定：单表 >5000万行或 >100GB → 分区/归档；跨库事务 → 拆分或最终一致
   ```
2. **存储选型档位表**（评审必须对号入座，回答"当前选型死于哪档"）：

   | 档位 | 典型形态 | 存储/检索配套基线 |
   |------|----------|-------------------|
   | ≤千级 QPS（万级数据） | 单机库+文件 | 单实例 PG/MySQL+本地索引可活 |
   | 十万级 QPS | 缓存+主从 | Redis前置、读写分离、分库、ES承接全文/词法检索、消息队列削峰 |
   | 百万级 QPS | 分布式全家桶 | 单元化/LCache多层缓存、MySQL 分片(ShardingSphere)、ES集群、Kafka、对象存储 |
   | 千万级 QPS | 自研/极致分层 | CDN+边缘、多级缓存命中率>99%、按 key 哈希无状态存储、冷热分层、专用引擎(OLAP/倒排)按业务拆 |

   对项目的判定句式：**"当前实现第一断裂点在 [组件]，撑到 [档位] 需替换为 [方案]，依据算式 [xxx]"**。
3. **访问模式审查**：SELECT * 大字段、逐行写无批量、无事务批量写（半套数据）、`IN (N个占位符)` 无分批、
   每请求新建连接（无池化 DriverManager 类配置直接点名）、慢查询风险（函数包索引/隐式转换/深分页）。
4. **一致性与迁移**：多存储（DB+缓存+向量+倒排）写入顺序与补偿；schema 变更流程（启动即建表在生产是 ⚠️：
   滚动发布新旧版本共存的 DDL 兼容性）；数据迁移回滚方案是否存在。
5. **持久性与容灾**：单机无备份=🛑；备份存在但从未演练恢复=⚠️ 升 🔶。

## 🔒 安全（全员共管，独立成节）

- **鉴权与授权**：对外端点逐个过——无鉴权但能读数据=🔶；无鉴权且能写/能触发花钱任务/能读任意路径=🛑；
- **数据外泄链**：组合路径审计（"可注入内容到存储"+"存储内容会回流到响应"构成外泄链，
  单看每个端点都无害）；路径参数拼接防穿越；反序列化白名单；
- **注入面**：SQL 拼接、命令执行、SSRF（用户可控 URL 发起服务端请求）、提示注入（AI 项目：
  外部内容进 prompt 且模型有工具/文件权限时必须评估）；
- **密钥管理**：默认口令写进配置、密钥入库入 git、日志打印敏感字段；
- **供应链**：依赖版本是否有已知 CVE 的 majors 落后（只点 majors 与利用链，不逐包扫描）。

## 交叉裁决常用原则

- 性能争议 → 以算式与配置文件里的实际数值裁决，不以经验口头裁决；
- "将来上量再改"可接受的条件：当前接口边界已隔离该实现（换实现不改调用方），否则视为架构债 ⚠️；
- 产品坚持带险上线时，报告保留 🛑 原判 + 追加一行"业务已知悉并接受的豁免记录"，不擅自降级分类。
