# 新项目企业级底座落地（Bootstrap）

> 目标：新项目在写第一行业务代码**之前/同时**把企业级底座铺完，使"上线必解"类问题从源头不发生。
> 与 `enterprise-project-review` 形成闭环：本 skill 负责不犯那些错，评审 skill 负责验证没犯。

## 开工前必问（缺一先问，禁止假设）

1. **技术形态**：语言/框架（默认按用户现有栈，如 Spring Boot 3.x + Java 21）；
2. **部署目标**：单机 / Docker / K8s——决定配置注入、探针、优雅停机的做法；
3. **预期量级**：当前档位（≤千 / 十万 / 百万 QPS）——底座深度按档位取，不过度建设也不裸奔；
4. **外部依赖**：DB / 缓存 / 向量库 / LLM API / MQ——每项都要走第 3、5、6 节规范。

## 落地顺序与规范（按依赖排序执行）

### 1. 仓库工程底座
- `.gitignore` 先于首次提交（含 `.env`、本地数据目录、密钥文件模式 `*key*/*secret*/*.pem`）；
- README 固定四节：快速开始（真实验证过的命令）/ 配置参考表（键、默认值、何时改）/
  架构与决策 / 已知局限——**配置参考表与 application.yml 由同一次改动维护，防漂移**；
- 模块划分：父工程只管版本治理（BOM import），**依赖由子模块自选**，禁止父级强加 web/model starter。

### 2. 配置治理（本项目评审的头号教训，最高优先级）
- **默认必须安全且可跑**：默认 profile = 零外部依赖模式（内存/本地实现），
  持久化/生产形态一律放独立 profile（`-prod`、`-postgres`），禁止把个人环境的值做成全局默认；
- 每个开关三处一致：代码默认值 = yml 值 = 注释/文档声称值，落地后逐项核对一遍；
- 空 profile / 死配置禁止入库；外部依赖一律环境变量注入，带**可启动的占位默认**
  （占位值只允许"首次调用才报错"，不允许"启动即崩"或"静默成功"）；
- 反例判据：新用户 clone 后按 README 执行 → 拿到堆栈 = 本节全部重做。

### 3. 外部调用规范（写成团队基类/工具，不许逐处手搓）
每个出网点（HTTP/DB/模型 API）强制四件套：**超时 + 捕获 + 降级 + 重试策略**。
- HTTP 客户端统一配置 connect/read timeout（Spring `RestClient`/`WebClient` 显式 build 超时，
  禁止裸 `create()`）；
- 降级路径必须真实 catch `连接拒绝/超时/协议异常` 三类，注释声称的降级要有单测钉住；
- 失败降级时**记录并露出降级标志**，禁止静默返回空集合（返回 `{degraded: true}` 也比空表强）。

### 4. 统一异常边界
- 全局 `@RestControllerAdvice`（或等价物）：错误响应带 `code/message/traceId`，禁止裸堆栈出网；
- 入参校验在入口层完成（`@Valid`/手工校验），null/超长/路径穿越（`../`）三类在过滤器层兜底；
- 文件路径类参数：白名单根目录 + normalize 后前缀校验，收敛为一个工具函数，禁止散点拼接。

### 5. 安全底座（第一天就装，不是上线前补）
- API-key / Token 过滤器骨架（哪怕本地环境先放行，代码和开关必须就位：`security.enabled=false`）；
- 密钥只从环境变量/密钥管理器注入，配置文件里只允许 `${VAR:占位}` 形式；
- 危险端点（写数据/触发花钱任务/读任意路径）在路由表上打 `SENSITIVE` 标记，鉴权上线时按标记收口；
- 日志脱敏约定：禁止输出 prompt 原文、文档全文、手机号/身份证段。

### 6. 可观测性
- 引入 actuator（或等价）：health(liveness/readiness 分开) + metrics + 慢请求日志；
- 结构化日志 + traceId 贯穿（MDC），对外响应头回传 traceId；
- 关键链路四金指标口径先定义：QPS / RT(P50、P99) / 错误率 / 饱和度（线程池、连接池使用率）——
  **每个耗时数字只有一个统计口径并写进注释**，杜绝"两套延迟数字"。

### 7. 存储与数据
- 连接池从第一天用 HikariCP（或等价），配置最大连接数与 DB 侧 `max_connections` 的换算注释；
- 批量写必须 batch + 事务（多存储写入定义顺序：持久化存储 → 缓存/索引，并写补偿/重建入口）；
- schema 演进用迁移工具（Flyway/Liquibase），**禁止生产"启动即建表"**；本地可留 `initSchema` 开关；
- `IN` 列表分批（≤1000/批）；大字段查询禁止 `SELECT *`，收敛在 DAO 层统一防。

### 8. CI 与测试对称
- 首次提交即带 CI（GitHub Actions 等）：构建 + 全模块测试 + 配置一致性冒烟
  （可用脚本断言 yml 关键默认值）；
- **测试对称纪律**：每个模块提交代码的同时至少一个测试类，空 test 目录 = 不合格；
- 对外契约（API schema / MCP tools / 消息格式）用契约测试锁定，改契约必先红。

### 9. 部署形态
- compose / K8s manifests **随仓库提供**（可注释掉非必需服务），禁止"在你机器上能跑"式部署；
- 优雅停机：`server.shutdown=graceful` + 连接 drain；长任务定义中断恢复策略（重跑幂等 or 断点续跑）；
- 启动自检 Runner：打印"当前 profile / 各外部依赖连通状态 / 关键开关值"，日志第一屏可判环境。

### 10. 交付自检（DoD）
完成后逐项核对 [BOOTSTRAP-CHECKLIST.md](BOOTSTRAP-CHECKLIST.md)，并建议立即跑一轮
`enterprise-project-review` 做首飞验证——**落地当天 drift-check 一次，防止边写业务边腐化**。

## 档位裁剪原则

| 量级档位 | 必做节 | 可延后节 |
|----------|--------|----------|
| ≤千 QPS（内部/学习） | 1/2/3/4/8/10 | 6(仅liveness+慢日志)、7(单机库)、9(compose即可) |
| 十万 QPS | 全部 | K8s/多活 |
| 百万+ QPS | 全部 + 单元化/多层缓存/异步化预埋 | —— |

裁剪只允许"延后"，不允许"跳过"：每个延后项在 README 已知局限里挂账，防止变成无痕裸奔。
