# 企业级项目双视角评审（产品 × 研发）

## 三条铁律（先于一切步骤）

1. **证据优先**：每条结论必须钉到具体文件与配置行（Markdown 文件链接），禁止"感觉良好"式评语；
   没读过代码就不得对该模块下结论。
2. **承诺必验**：README / pom 描述 / 代码注释里的每一个可验证承诺（默认值、端口、"开箱即跑"、
   "已修复"），都必须与实际代码逐项对照。**承诺与交付不符本身就是最高价值发现**。
3. **默认路径优先**：评审的第一入口永远是"新用户按文档从零开始"的那条路径（clone → 配环境变量 →
   启动 → 调第一个接口）。默认配置导致的启动失败/功能失效，优先级高于一切风格问题。

## 评审流程

### Step 1 — 全量侦察（并行读取，禁止猜）

按此顺序建立全景：

```
- [ ] 根构建文件（pom.xml / package.json / build.gradle）：版本治理、模块划分、依赖是否下沉到父级
- [ ] 所有 application.yml / .env / 配置文件：⚠️ 重点看每个开关的"实际默认值"与"注释声称的默认值"是否一致
- [ ] README / docs：提取所有可验证承诺（默认值、端口、快速开始命令、数字指标）
- [ ] 启动入口 + Bean 装配（@Configuration / 条件装配）：默认 profile 下每个必需 Bean 是否真的存在
- [ ] 核心业务 Service：主链路逐条读（输入校验 → 处理 → 外部调用 → 异常路径 → 输出落盘）
- [ ] 对外入口（Controller / RPC / MCP tools）：鉴权、参数校验、错误语义
- [ ] 测试目录：存在性与覆盖面，测试覆盖不到的模块单独标记
```

### Step 2 — 默认路径推演

模拟新人，纸面执行 README 快速开始的每一步，逐问：
- 此步骤依赖的外部组件（DB/缓存/MQ/模型服务）在默认配置下是否必需？没装会怎样？
- 文档给的命令与代码实际默认值是否匹配（端口、开关、路径）？
- 静默失败点：哪些错误路径不报错而是返回空结果/退化行为？

### Step 3 — 产品视角评审

按 [CHECKLISTS.md](CHECKLISTS.md) 的"产品视角八问"逐项分析，核心是：
**定位可信度（宣传 vs 证据）、用户旅程完整性、文档作为产品界面的漂移度、风险披露与宣传口径是否一致。**

### Step 4 — 研发视角评审

按 [CHECKLISTS.md](CHECKLISTS.md) 的"研发视角九域"逐项分析，核心是：
**正确性（并发/边界/幂等）、降级路径是否真实存在、数据一致性、可观测性、安全面、测试不对称。**

### Step 5 — 输出评审报告

使用下方模板。写作要求：结论放最前；每条问题=「现象 + 文件证据 + 为什么严重 + 修复动作」；
不同视角发现的同源问题（如"默认值漂移"同时是文档问题与启动问题）要合并指出，体现系统性。

## 报告模板

```markdown
## 🎯 总体判定
[一句话：项目的真实水位 vs 自我标称的水位，差距在哪里]

## 🔴 阻断级发现（双方视角一致认定）
### N. [标题]
[现象描述 + 复现推演] 证据：[文件链接]
[影响面：谁会死、怎么死、静默还是显式]

## 🧑‍💼 资深产品视角
**定位与证据**：…  **文档漂移**：…  **用户旅程**：…  **风险披露一致性**：…

## 👨‍💻 资深研发视角
**正确性/并发**：…  **降级与容错**：…  **数据一致性**：…  **安全**：…  **测试不对称**：…

## 优先级行动清单
| # | 严重度 | 行动 | 预估成本 |
|---|--------|------|----------|
| 1 | 🚨 阻断 | … | 小时级 |
```

严重度定义（全项目统一，不得私设）：
- 🚨 **阻断**：默认路径启动失败 / 数据损坏 / 安全裸奔 / 核心承诺完全未实现
- 🔴 **高**：主链路上的静默错误、核心卖点缺乏证据、跨文档大面积漂移
- 🟠 **中**：非默认路径的容错缺失、异步/同步模型选错、部分失败连坐
- 🟡 **低**：卫生问题（死代码、杂散文件、无 CI）与战略级建议

## 反模式（评审者自己不能犯的错）

- ❌ 只评代码风格与命名，不碰默认配置与启动路径
- ❌ 把 README 的说法当作事实（文档说"默认关闭"≠默认关闭，去 yml 里看）
- ❌ 发现文档与代码不一致时只报"代码问题"——漂移本身要同时记在文档账上
- ❌ 罗列 50 条低价值问题稀释 3 条阻断级发现——报告的价值密度由严重度排序保证
- ❌ 给出"建议重构"这类无执行成本的空话——每条修复动作必须可当天开工
