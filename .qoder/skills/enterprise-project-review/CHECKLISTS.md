# 双视角评审检查清单

> 用法：Step 3 / Step 4 逐项过一遍，每项给出「✅ 满足 / ⚠️ 部分 / ❌ 缺失 / 🔍 未验证」四态结论之一，
> ⚠️ 与 ❌ 必须附文件证据；证据不足标 🔍，禁止脑补成 ✅。

## 产品视角八问

| # | 问题 | 判据（什么算 ❌） |
|---|------|------------------|
| P1 | 核心定位有证据吗？ | 宣传的关键能力（如"评测驱动""自动化"）在仓库里找不到一次完整执行记录/产出数据 |
| P2 | 文档与代码漂移几处？ | README 配置表、pom 描述、代码注释中的默认值/端口/路径与真实值不一致，每一处都单独列出 |
| P3 | 首次用户体验成立吗？ | 按快速开始走不通：依赖隐性外部组件、命令过时、失败无诊断信息（静默空结果最恶劣） |
| P4 | 宣传口径与风险披露一致吗？ | 一处写 "Production-grade"，另一处 Known Limitations 承认无鉴权——自相矛盾必须点名 |
| P5 | 用户旅程断在哪一环？ | 长任务同步阻塞 HTTP、批量操作一坏全坏、无任务状态/无部分产出、错误直达用户无兜底 |
| P6 | 产品边界与个人环境耦合吗？ | 文档出现个人绝对路径、仓库引用不存在的文件（如 compose 文件）、只在单机成立的默认值 |
| P7 | 多产品线是否有统一价值主张？ | 同仓库模块之间零联动、各自为政，路线图与现状不符 |
| P8 | 数字指标可信吗？ | 指标无可追溯来源（无 runId/无采样说明）、同一系统两套口径混用 |

## 研发视角九域

| # | 域 | 检查点 |
|---|----|--------|
| E1 | 启动正确性 | 默认 profile 下所有必需 Bean 是否条件装配可达；急切初始化（建表/连库/预热）在依赖缺失时是否炸启动 |
| E2 | 外部调用容错 | 每个 HTTP/RPC/DB 调用是否有：超时设置、异常捕获、降级路径、重试策略。**注释声称的降级必须验证代码里真的 catch 了** |
| E3 | 并发与共享状态 | 懒加载缓存是否线程安全；单例里的可变 Map/List；"读不加锁+写替换引用"的可见性是否真的靠 volatile/原子替换 |
| E4 | 数据一致性 | 多存储写入（DB+缓存+索引）有无事务/顺序/补偿；批量写是否逐条无事务留下半套数据；删除路径与写入路径是否对称 |
| E5 | 幂等与键设计 | 业务唯一键是否会碰撞（如只取文件名丢弃路径）；重复提交/重灌是否真幂等；确定性 ID 的指纹输入是否完备 |
| E6 | 输入边界 | 对外参数无校验（null/超长/负数）、路径拼接未防穿越（../）、SQL IN 列表无分批、越界下标直接使用外部返回 |
| E7 | 静默失败 | 解析异常吞行、空集合返回代替报错、-1/0 语义混淆、WARN 噪音掩盖真实故障 |
| E8 | 复杂度成本 | 逐条循环全量重读文件（O(n²) I/O）、每请求新建连接无池化、无界内存累积 |
| E9 | 工程纪律 | 测试覆盖与模块数对称（某模块 0 测试必须点名）；死代码/空 profile/杂散文件；无 CI；结构化输出/LLM 返回值无空校验即解引用 |

## 交叉合并规则

同一根因被双视角命中时合并为一条，标注"产品账 + 工程账双记"：
- 默认值漂移 → P2 + E1（典型：一次改动同时破坏文档承诺与启动路径）
- 降级未实现 → P1 + E2（承诺的功能只是注释）
- 无鉴权+宣传企业级 → P4 + E6
- 静默空结果 → P3 + E7

## 严重度判据速查

- 🚨 阻断：满足任一——默认路径无法启动 / 正常使用会损坏或丢数据 / 未鉴权即可读改写敏感资源 / 核心卖点完全未实现
- 🔴 高：主链路存在（但非默认触发）、核心指标无证据、文档漂移 ≥3 处
- 🟠 中：异常路径体验问题、部分失败连坐、同步阻塞长任务
- 🟡 低：卫生与战略项，修复动作可延后但需挂账
